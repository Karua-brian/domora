## Confirmed strengths

- PostgreSQL enforces Owner/Member/Finance values and at most one Owner with `CK_OrganizationMemberships_Role` and `IX_OrganizationMemberships_OrganizationId_Owner`.
- Supported membership mutations use a shared ownership guard and organization-row `FOR UPDATE` lock. Ownership transfer saves the demotion before promotion within the same transaction.
- Financial command handlers authorize against persisted membership roles. JWTs supply the user identity; they do not carry organization roles.
- The payment-void path keeps the payment and allocation rows, records actor/time/reason in `PaymentVoid`, and calculates effective invoice allocations using active payments.
- RLS is forced on core organization-scoped tables, and composite foreign keys prevent payment allocations/voids from crossing organization boundaries.
- The test rebuild script uses a dedicated administrator and checks endpoint/database/cluster identity, credentials-file mode/owner, and active sessions before dropping only the hardcoded test database.
